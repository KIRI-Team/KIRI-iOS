# 기능명세서 ver 1.4 (10월 15일 기준) - 최신 기준

날짜: 2026년 10월 19일 오후 8:53
선택: 1.4

### 변경 사항(ver 1.3 → ver 1.4)

기존 기능명세에서 실제 피그마 플로우와 맞지 않거나 개발 단계에서 해석이 갈릴 수 있었던 **가족공간, 데일리 질문, 미션 생성·추천, 버킷, 일정 초대, 약속 당일, 리뷰, 알림, 취향 설정** 정책을 전반적으로 구체화했습니다.

가족공간은 생성 후 **초대 링크와 초대코드를 모두 제공**합니다. 초대 링크로 진입한 경우 링크에 포함된 초대 정보가 자동 적용되어 코드를 다시 입력하지 않고, 일반 가입 사용자는 온보딩에서 가족코드를 직접 입력해 참여할 수 있습니다. 초대 링크와 코드는 7일간 유효하며 가족공간당 활성 링크/코드 1세트만 유지합니다. 가족공간 생성자가 탈퇴하면 현재 구성원 중 가장 먼저 참여한 사용자에게 소유권을 이전하고, 남은 구성원이 없으면 가족공간을 종료합니다. 프로필 이미지를 직접 등록하거나 수정하는 기능은 사용하지 않고 엄마/아빠/아들/딸 역할별 KIRI 기본 캐릭터를 자동 적용하며 같은 역할은 닉네임으로 구분합니다. 생년월일과 성별도 별도로 수집하지 않습니다.

둘러보기 상태에서는 가족 질문을 배정하거나 답변하지 않으며 스토리 링도 표시하지 않습니다. 사용자가 실제 가족공간을 생성하거나 참여한 시점부터 가족 질문 기능이 활성화됩니다. **가족 데일리 질문은 매일 가족별 공통 텍스트 질문 1개가 배정되고 각 구성원이 같은 질문에 각자 텍스트로 답변하는 구조**로 통일했습니다. 객관식·사진 답변 등 별도의 질문 유형은 사용하지 않습니다. 기존 가족에 당일 새 구성원이 참여하면 새로운 질문을 만들지 않고 해당 가족에 이미 배정된 그날의 질문을 동일하게 받습니다. 작성과 수정은 당일까지만 가능하고, 지난 질문과 답변은 기록/캘린더에서 날짜별로 다시 확인할 수 있습니다. 날짜가 지나면 읽기 전용이며 미답변자는 `미답변`으로 표시합니다. 탈퇴한 구성원의 과거 답변은 개인정보 정책에 따라 `탈퇴한 멤버`로 익명화하여 기록을 유지합니다.

데일리 질문 전체를 추천용으로 사용하지도 않습니다. 질문의 기본 목적은 가족 구성원끼리 서로의 생각과 취향을 알아가는 것이고, 그중 **취향 파악용으로 사전에 지정된 질문에서 활동·장소·음식 등의 선호가 명확하게 확인되는 경우에만 보조 취향 신호로 활용**합니다. 추억이나 감정, 가족관계 등에 관한 자유로운 텍스트를 임의로 취향으로 추론하지 않습니다. 질문에 답하지 않더라도 주간 미션은 정상적으로 제공됩니다.

미션 구조는 `장소 하나에 여러 미션을 수동으로 만드는 방식`이 아니라 **외부 API·공공데이터 증분 수집 → 신규/변경 데이터 감지 → KIRI 미션 자동 생성 → 추천 후보 등록 → 가족 추천/미션탭 노출 → 버킷 저장 → 일정 → 활동 → 리뷰** 흐름으로 정리했습니다. 외부 장소나 행사 하나를 사용자에게 수행 가능한 하나의 KIRI 미션으로 가공하며, `한강 뚜벅뚜벅 축제 → 한강 뚜벅뚜벅 축제 방문하기`처럼 원본 고유명을 최대한 유지하면서 콘텐츠 유형에 맞는 행동형 제목을 생성합니다. 운영자가 매번 미션을 직접 작성하는 방식은 사용하지 않고 정상적인 데이터는 자동 등록하며, 정보가 부족하거나 분류가 모호한 경우만 별도 확인 대상으로 처리합니다.

미션 카테고리는 **전시·문화 / 팝업·행사 / 공연 / 맛집·카페 / 산책·야외 / 체험·놀거리** 6개로 통일했습니다. 미션 내부의 `필수 활동`은 별도 미션이 아니라 해당 미션에서 가족이 함께 해볼 수 있는 세부 활동입니다. 외부 데이터의 상세 설명·프로그램·시설 등 확인 가능한 정보를 우선 사용하며 존재하지 않는 특정 프로그램이나 시설을 임의로 만들어내지 않습니다. 참여 가족 조합에 따라 탐색 단계에서 미션을 다르게 추천하는 기능은 제거하고, 실제 참여 구성원은 일정을 생성할 때 결정합니다.

개인화 추천을 위해 마이페이지에 **내 취향 설정**을 두고 언제든 수정할 수 있도록 했습니다. 항목은 `선호 활동 / 실내·야외 / 활동량 / 비용 / 활동시간` 5개이며, 선호 활동은 KIRI 6개 미션 카테고리 중 최대 3개를 선택합니다. 추천에는 내 취향 설정을 우선적으로 활용하고, 취향 파악용 데일리 질문의 보조 신호와 버킷 저장, 일정, 실제 활동 완료, 별점, 재참여 의향 등의 행동 데이터를 함께 사용합니다. **KIRI Pick은 가족 개인화 주간 미션과 별개인 운영 측 공통 큐레이션 콘텐츠**로 구분합니다.

버킷 구조는 가족 전체가 하나의 항목을 공동 저장하는 방식이 아니라 **각 사용자가 자신의 이름으로 미션을 저장하고, 가족 버킷리스트 화면에서 가족 구성원들의 저장 항목을 통합해서 보여주는 구조**로 확정했습니다. 따라서 엄마와 아빠가 같은 미션을 각각 저장하는 것도 가능합니다. 동일 사용자가 동일 미션을 중복 저장하는 것만 제한합니다. 가족 버킷 화면에서는 `전체 / 엄마 / 아빠 / 첫째 / 둘째 ...`처럼 저장자별 필터(저장자는 역할이 아니라 닉네임임)를 제공하고 각 카드에는 `아빠가 저장했어요`와 같이 실제 저장자를 표시합니다. 버킷 저장자와 일정 제안자는 같을 필요가 없으므로 아빠가 저장한 미션을 딸이 보고 일정을 제안하는 것도 가능합니다. 탈퇴한 사용자가 저장했던 항목은 저장자 이름 대신 `탈퇴한 멤버`로 표시합니다.

일정 생성 플로우는 피그마 기준으로 **버킷에서 미션 선택 → 일정 잡기 → 날짜·시간 선택 → 제안할 가족 구성원 선택 → 가족에게 한 줄 작성 → 초대장 생성 및 확인 → 요청 보내기** 순서로 통일했습니다. 가족 전체에게 무조건 요청을 보내는 구조가 아니라 **일정 제안자가 선택한 가족 구성원에게만 일정 요청을 보냅니다.** 제안자는 자동 참여 상태이고 선택되지 않은 가족 구성원은 해당 일정의 응답 대상이 아닙니다. 앱으로 보내기를 선택하면 KIRI Push와 앱 내 알림을 통해 전달하고, 카카오톡 보내기는 초대 내용을 외부로 공유하는 보조 수단으로 사용합니다. 실제 `참여 / 대기 / 불참` 응답과 일정 상태 처리는 KIRI 앱 안에서 이루어집니다.

일정 응답은 **참여 / 대기 / 불참** 3개를 유지하고 아직 아무 선택도 하지 않은 `미응답`과 사용자가 직접 선택한 `대기`를 구분합니다. 제안자는 자동 참여이며, 선택된 가족 중 제안자 외 한 명 이상이 참여하면 일정은 즉시 확정됩니다. 응답 마감은 **일정 시작 24시간 전**이고, 24시간 이내에 만들어진 일정은 일정 시작 시각까지 응답할 수 있습니다. 마감까지 제안자 외 참여자가 없다면 미확정 처리하고 대기와 미응답 구성원은 최종 참여자에 포함하지 않습니다. 날짜·시간·장소·참여자처럼 핵심 일정 정보가 변경되면 기존 참여자는 `재확인 필요` 상태로 전환하며, 최초 초대에 응답하지 않은 `미응답`과 화면에서도 구분합니다.

확정된 일정 중 현재 사용자가 최종 참여자인 일정은 **시작 D-7부터 홈 상단에 노출**합니다. 여러 일정이 있으면 가장 가까운 일정 하나를 우선 보여주고, 당일에는 같은 영역을 오늘의 일정으로 전환하여 약속 당일 화면으로 연결합니다. 아직 응답하지 않은 초대는 확정 일정과 섞지 않고 `응답이 필요한 일정`으로 별도 처리합니다. 일정의 시작 여부는 별도의 START 버튼 클릭이 아니라 등록된 일정 시작 시각을 기준으로 판단합니다.

약속 당일에는 **필수 활동 / 필수템 / 근처 놀거리 추천**을 제공합니다. 필수 활동과 필수템은 구성원별 체크 완료 상태를 저장하는 별도의 체크리스트가 아니라 가족이 함께 참고하는 일정 정보입니다. 필수템은 미션 생성 시 날씨를 추측해서 고정하지 않고 일정 장소·날짜·시간과 미션 특성을 기준으로 약속 시점에 제공합니다. 걷기가 많은 활동이면 편한 신발, 야외 일정에 비가 예상되면 우산처럼 명확한 조건을 사용합니다. 날씨 조회는 사용자 현재 위치가 아니라 **일정 장소 좌표와 일정 날짜·시간**을 기준으로 하며, 예보 가능 기간에 들어온 뒤 조회하고 약속 당일 최신 예보를 다시 확인합니다. 날씨 API에 실패해도 약속 당일 화면은 정상적으로 제공하고 날씨 기반 준비물만 제외합니다.

`컨디션 커스텀하기` 기능은 유지하되 메인 미션 자체를 변경하는 기능으로 사용하지 않습니다. `걸음 수 낮추기 / 휴식 시간 늘리기 / 예산 낮추기 / 사람 많은 곳 피하기` 등의 조건을 적용하면 **현재 일정 장소 주변의 추가 추천 결과를 재정렬**합니다. 걸음 수를 낮추면 가까운 후보, 휴식을 늘리면 카페·공원 등 머무르기 좋은 후보, 예산을 낮추면 무료·저비용 후보를 우선합니다. 혼잡도는 신뢰할 수 있는 데이터가 있을 때만 적용하고 AI가 임의로 추정하지 않습니다. 근처 놀거리 역시 미션 생성 시 고정하지 않고 일정 장소를 기준으로 동적으로 조회합니다.

버킷 항목은 일정이 생성됐다고 바로 사라지지 않습니다. **저장 → 일정 연결 → 활동 → 유효 리뷰 등록 → 완료**흐름으로 관리하며, 완료된 항목도 자동 삭제하지 않고 `완료` 상태로 남깁니다. 피그마의 `종료된 일정` 표기는 `완료`로 변경합니다. 하나의 버킷 항목은 하나의 활동 흐름으로 관리하고 완료된 동일 버킷에서 바로 재일정을 만드는 재방문 기능은 두지 않습니다. 예정 일정이 연결된 버킷을 바로 삭제하여 일정만 고아 상태로 남기는 것도 허용하지 않고, 먼저 일정 취소 또는 연결 관계를 정리한 뒤 버킷을 삭제하도록 합니다.

외부 행사 자체가 취소되거나 운영기간이 변경되어 예정 날짜에 수행할 수 없게 된 경우에는 해당 미션을 신규 추천에서 제외합니다. 이미 `CONFIRMED` 또는 `PENDING_RESPONSE` 일정과 연결되어 있다면 사용자에게 외부 행사 변경/취소 사실을 알립니다. 외부 정보 변경만으로 가족 일정을 자동 취소하지 않고 사용자가 일정 상세에서 변경 또는 취소할 수 있도록 합니다. 가족이 직접 취소한 `일정 취소`와 외부 콘텐츠 자체가 취소된 `미션/행사 취소`는 별개의 상태로 구분합니다.

리뷰 완료 조건은 데일리 질문과 완전히 분리했습니다. **활동 리뷰는 사진 1장 이상 + 비어 있지 않은 기록 + 별점 1~5점 + 재참여 의향 예/아니오를 모두 필수로 입력**합니다. 참여자 중 최소 한 명이 이 조건을 충족하는 유효 리뷰를 등록하면 해당 활동을 완료 상태로 처리합니다. 단순히 일정 시간이 지났다는 이유만으로 자동 완료하지 않습니다. 예상 걸음 수와 활동시간 역시 운영자가 미션마다 수동으로 입력하는 것을 기본으로 하지 않고 공식 거리·코스·프로그램 소요시간 등을 우선 사용하며, 근거가 부족하면 지나치게 정밀한 숫자 대신 보수적인 예상값이나 범위를 제공합니다.

마지막으로 Push만으로 끝나지 않도록 **앱 내 알림함**을 추가했습니다. 일정 초대, 일정 변경 및 재확인, 일정 취소, 콕 찌르기, 외부 행사 중요 변경 등 다시 확인할 필요가 있는 이벤트를 알림함에 저장하고 관련 화면으로 연결합니다. 읽음/안읽음과 모두 읽기를 지원하며 Push 전송과 앱 내 알림 저장은 별개로 처리해 Push 발송에 실패하더라도 알림 기록은 유지합니다.

### 변경 사항(09.30 → 10.05)

**[MIS-13] 미션 자동 생성, 변경**

기존 주소 또는 좌표 중 하나만 존재해도 장소 정보가 유효한 것으로 판단하던 기준을 유효한 좌표 필수, 주소 선택으로 변경함, 일반 음식점과 관광지는 가족 전용 시설 여부를 별도로 검수하지 않고 다른 자동 검증 조건을 충족하면 공개하도록 변경함

**[MIS-16] 장소 및 미션 중복 판정, 보완**

주소가 없는 장소도 유효한 좌표와 장소명을 기준으로 중복 후보를 확인할 수 있도록 보완함, 기존 100m 기준은 동일 장소를 확정하는 조건이 아닌 중복 후보를 찾는 조건으로 적용하고 장소명이 다르거나 동일 장소 여부가 불명확하면 자동 병합하지 않도록 명시함

**[MIS-17] 행사 종료 및 상태 갱신, 보완**

TourAPI에서 행사 취소 여부를 별도 값으로 제공하지 않는 점을 반영해 제목에 [취소], (행사취소) 등 명확한 취소 표시가 있는 경우에만 외부 취소로 처리하도록 기준을 구체화함, 단순 비공개 전환이나 원본 조회 실패는 행사 취소로 확정하지 않고 검수 대상으로 분리하며, 확인 전까지 신규 탐색과 추천에서는 제외하도록 보완함

**[MIS-18] 자동 검수 및 공개 판정, 변경**

기존 일반 음식점과 관광지를 가족 활동 적합성 확인 대상으로 분류하던 기준을 변경해 주점, 클럽, 카지노 등 명확한 제외 업종만 자동 제외하고 일반 음식점과 관광지는 정상 검증을 통과하면 자동 공개하도록 수정함, 장소 정보 검증도 주소 또는 좌표에서 유효한 좌표 필수로 변경하고 주소 누락만으로 검수 대상으로 분류하지 않도록 수정함

관리자 페이지는 추후 개발 예정이며 구체적인 기능과 정책이 확정되면 별도 명세로 전달할 예정임
